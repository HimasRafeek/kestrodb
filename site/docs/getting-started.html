Getting started

Build the engine once, open a database file from Node.js, and run your first SQL statements. This takes a few minutes on a machine with a C++ toolchain.

Requirements

Required everywhere: CMake 3.20+, a C++17 compiler and Node.js 22 or newer. BLAKE3 and the Node-API headers are bundled, so KestroDB itself has no npm dependencies. Only 64-bit targets are supported.

OSPrerequisites
Windows x64Visual Studio 2022 Build Tools with “Desktop development with C++” and a Windows SDK; CMake on PATH.
LinuxGCC or Clang, Make or Ninja, OpenSSL 3 development headers (libssl-dev).
macOSXcode Command Line Tools and CMake.

Platform status. 0.9.0 is built and tested on Windows 10 (MSVC 2022) and on Linux (GCC 13, Ubuntu 24.04 under WSL2, with scripts/linux-check.sh). CI builds and tests Linux x64, Linux ARM64 and Windows on every push and pull request, with AddressSanitizer + UBSan, ThreadSanitizer and fuzzing. macOS passed on GitHub’s runner through 2026-11-19 and is no longer run (not a target for now). It has not yet run real production workloads for long. See platform status.

Build and test

From the project folder:

npm run build
npm test
node example.mjs
  • npm run build puts the Node addon (kestro.node), the worker and the native tests in bin/.
  • npm test runs the native C++ suite (through CTest) and the Node suite in tests/.
  • node example.mjs tours the key/value API in a temporary folder.

bin/ is build output and is not part of the repository. To skip the build, use the prebuilt binaries attached to each GitHub release (Windows x64, Linux x64 and Linux arm64 archives, and an npm package with prebuilt binaries); the Windows binaries need only Windows system DLLs.

Your first database in Node.js

Database (in index.mjs, the package’s main export kestrodb) runs the engine inside your Node process. Calls are synchronous, like node:sqlite’s DatabaseSync, and a write returns only once it is durable on disk.

import {Database} from 'kestrodb';   // or './index.mjs' inside this folder

const db = new Database('./app.kdb', {create: true});   // first run; later omit create

db.sql('CREATE TABLE users (id INTEGER PRIMARY KEY, email TEXT UNIQUE, name TEXT, age INT)');
db.sql('INSERT INTO users (email, name, age) VALUES (?, ?, ?)', ['kestro@example.com', 'Kestro', 30]);
                                                   // → {changes: 1, lastInsertId: 1}
db.sql('SELECT * FROM users WHERE age >= ? ORDER BY age DESC LIMIT 10', [18]);
                                                   // → {rows: [{id: 1, email: ..., name: 'Kestro', age: 30}]}
db.sql('UPDATE users SET age = age + 1 WHERE id = ?', [1]);
db.sql('CREATE INDEX ON users (age)');

db.close();
  • create: true creates a new file and refuses to overwrite an existing one. Leave it out to open an existing database.
  • One process owns a database file at a time; a second owner gets LOCKED. To share a database between processes, run kestro-server.
  • close() waits for queued async writes, then closes. Database also supports using.

The key/value API

Next to SQL, a key/value API (set, get, getMany, batch) gives the fastest access by key. This is the tour from example.mjs:

// node example.mjs — a tour of the API in a temporary folder.
import {Database} from './index.mjs';
import {mkdtempSync} from 'node:fs';
import {tmpdir} from 'node:os';
import {join} from 'node:path';

const dir = mkdtempSync(join(tmpdir(), 'kestrodb-demo-'));
const db = new Database(join(dir, 'app.kdb'), {create: true});
try {
  db.batch(Array.from({length: 256}, (_, i) => ({type: 'set', collection: 'items', key: String(i), value: {title: `Item ${i}`, count: 0}})));
  const before = db.get('items', '0');
  db.set('items', '0', {...before.value, count: 1}, {expectedVersion: before.version});  // fails if someone changed it meanwhile
  console.log(db.getMany('items', ['0', '1', 'missing']));
  await Promise.all(['a', 'b', 'c'].map(k => db.setAsync('items', k, {k})));            // concurrent writes, one commit
  db.delete('items', '255');
  db.backup(join(dir, 'backup.kdb'));
  db.compactTo(join(dir, 'compact.kdb'));
  console.log({record: db.get('items', '0'), stats: db.stats(), verification: db.verify(), directory: dir});
} finally {
  db.close();
}

Every method is described in the Node.js API reference.

SQL quick tour

KestroDB speaks the common core of MySQL, PostgreSQL and SQLite. The same statements work from every client: db.sql() in Node (Database and RemoteDB), $db->sql() in PHP and db.sql() in Python. Always pass values as parameters (?, $1 or :name), never by pasting them into the SQL text.

Create a table

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  name VARCHAR(100),
  age INT,
  plan TEXT NOT NULL DEFAULT 'free'
);

Every table has an id primary key. Declared columns are enforced: INSERT and UPDATE check each declared column’s type and NOT NULL, and fill DEFAULT values for omitted columns. Values are not converted, so text is not an integer:

INSERT INTO users (email, age) VALUES ('a@example.com', 30);     -- plan gets its DEFAULT, 'free'
INSERT INTO users (email, age) VALUES ('b@example.com', '30');   -- rejected: '30' is text, age is INT

Rows are still JSON documents, so a row may also hold undeclared columns, nested objects and arrays. UNIQUE columns get a unique index. CHECK, FOREIGN KEY and multi-column UNIQUE constraints are enforced too:

CREATE TABLE orders (
  id INTEGER PRIMARY KEY,
  user_id INTEGER REFERENCES users (id) ON DELETE CASCADE,
  total REAL CHECK (total >= 0)
);

Change a table later with ALTER TABLE ... ADD / DROP / RENAME COLUMN, RENAME TO and ADD / DROP CONSTRAINT.

Insert and upsert

-- Insert one or many rows; leave id out and KestroDB assigns 1, 2, 3, ...
INSERT INTO users (email, name, age) VALUES (?, ?, ?), (?, ?, ?);

-- Upsert, in PostgreSQL, MySQL or SQLite syntax
INSERT INTO users (id, email, name) VALUES (?, ?, ?) ON CONFLICT (id) DO UPDATE SET name = excluded.name;
INSERT INTO users (id, email, name) VALUES (?, ?, ?) ON DUPLICATE KEY UPDATE name = VALUES(name);
REPLACE INTO users (id, email, name) VALUES (?, ?, ?);

Query

SELECT id, name, age * 2 AS double_age FROM users
  WHERE (city = 'Colombo' OR city = 'Kandy') AND age BETWEEN 18 AND 65 AND name LIKE 'Him%'
  ORDER BY age DESC, name LIMIT 20 OFFSET 40;

SELECT city, COUNT(*) AS n, AVG(age) AS avg_age FROM users
  GROUP BY city HAVING COUNT(*) > 10 ORDER BY n DESC;

SELECT name, city, RANK() OVER (PARTITION BY city ORDER BY age DESC) AS rank_in_city FROM users;

Change, index and remove

UPDATE users SET age = age + 1, name = ? WHERE id = ?;
DELETE FROM users WHERE last_seen < ?;

CREATE INDEX ON users (city);
CREATE UNIQUE INDEX users_email ON users (email);

Join and use subqueries

SELECT u.name, o.total FROM users u JOIN orders o ON o.user_id = u.id WHERE u.city = ?;
SELECT * FROM users WHERE id IN (SELECT user_id FROM orders WHERE total > ?);
SELECT u.name FROM users u WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

INNER, LEFT, RIGHT, FULL, CROSS and comma joins work with aliases, ON or USING; index the join columns. Subqueries may be correlated (naming the outer table, as in the last line).

Transactions

BEGIN;
UPDATE accounts SET balance = balance - ? WHERE id = ?;
UPDATE accounts SET balance = balance + ? WHERE id = ?;
COMMIT;            -- or ROLLBACK

A transaction belongs to its connection and commits atomically and durably; SAVEPOINT, ROLLBACK TO and RELEASE undo part of one. Plain BEGIN transactions write one at a time, so keep them short. BEGIN CONCURRENT transactions run side by side under snapshot isolation; one that loses a write conflict fails with CONFLICT at COMMIT and is run again. See SQL transactions.

What comes back

StatementResult
SELECT{"rows": [{...}, ...]}: one object per row
INSERT{"changes": n, "lastInsertId": id}
UPDATE, DELETE{"changes": n}
CREATE, DROP{"changes": 0} (DROP TABLE: rows removed)

Each statement is atomic and durable before it returns. Deferred constraints, NATURAL joins and full-text search are not supported yet; see the full list. Index the columns you filter on: a query that returns whole rows without an index reads and parses every row.
